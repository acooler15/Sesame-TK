# Sesame-TK 功能模块文档

> 本文档介绍芝麻粒-TK 的各个功能模块。所有功能模块均作为 `Model` 子类注册，通过 `model/ModelOrder.kt` 的 `array` 声明加载顺序，由 `Model.initAllModel()` 反射实例化。任务类统一继承 `ModelTask`，在支付宝内以 RPC 方式执行各类业务操作。

## 1. 模块体系

### 1.1 注册与生命周期

- **注册顺序**：`model/ModelOrder.kt` 的 `array` 固定了 15 个模块的加载顺序（即 §2 总览表顺序），`Model.initAllModel()` 按此反射实例化并登记到 `modelConfigMap` / `groupModelConfigMap`。
- **生命周期**：`prepare() → boot()`（仅启用的模块）→ `destroy()`，由 `Model.bootAllModel()` / `destroyAllModel()` 统一调度。
- **默认状态**：除「基础」模块默认启用外，**其余 14 个模块默认全部禁用**（`model/Model.kt` L16：`val defaultValue = "基础" == getName()`），需在配置 UI 中手动开启。
- **启用字段**：`Model.enableField`（code 为 `enable`）。基础模块显示名为「启用模块」，其他模块为「开启 + 模块名」。

### 1.2 分组（ModelGroup）

`model/ModelGroup.kt` 定义 8 个分组，用于 UI 分区展示：BASE（基础）/ FOREST（森林）/ FARM（庄园）/ STALL（新村）/ ORCHARD（农场）/ SPORTS（运动）/ MEMBER（会员）/ OTHER（其他）。

### 1.3 配置字段类型

各模块的配置项由 `ModelField<T>` 子类（`model/modelFieldExt/`）承载：`BooleanModelField`（开关）、`IntegerModelField`（整数）、`StringModelField` / `TextModelField`（文本）、`ChoiceModelField`（单选）、`SelectModelField` 系列（好友/道具选择）、`ListModelField` 系列（时间点列表）等。本文各模块小节中的**字段名均为代码中的 UI 显示名**，括号内为字段 code。

## 3. 基础组（BASE）

### 3.1 基础（BaseModel）

全局开关与通用运行配置，`model/BaseModel.kt`。字段实际定义在 `model/SesameConfig.kt`（`ApplicationHook.config` 持有），BaseModel 仅做聚合展示。核心配置项（UI 名 → code）：

**调度与时间**

- **手动触发目标应用运行**（`manualTriggerAutoSchedule`，默认 false）：手动执行后是否自动安排下次执行。
- **执行间隔(分钟)**（`checkInterval`，默认 50，范围 1~720）：两次主任务执行的最小间隔。
- **任务执行轮数**（`taskExecutionRounds`，默认 1，范围 1~99）：每轮主任务中各任务的执行轮数。
- **定时执行(关闭:-1)**（`execAtTimeList`，默认 12 个时间点：`0010/0030/0100/0700/0730/1200/1230/1700/1730/2000/2030/2359`）：优先于执行间隔的定点执行。
- **模块休眠时间(范围|关闭:-1)**（`modelSleepTime`，默认 `0200-0201`）：该时段暂停所有任务。
- **只收能量时间(范围|关闭:-1)**（`energyTime`，默认 `0700-0730`）：该时段内非森林任务被 `check()` 拦截，森林进入蹲点收取循环（`AntForest.check()` L610-615）。

**异常与超时**

- **超时重启**（`timeoutRestart`，默认 true）、**异常等待时间(分钟)**（`waitWhenException`，默认 60）、**开启异常通知**（`errNotify`，默认 false）、**异常次数阈值**（`setMaxErrorCount`，默认 8）。

**接口与调试**

- **使用新接口(最低支持v10.3.96.8100)**（`newRpc`，默认 true）：切换 `NewRpcBridge` / `OldRpcBridge`。
- **启用 WebView Hook**（`webViewDebug`，默认 false）。
- 仅 DEBUG 可见：**开启抓包(基于新接口)**（`debugMode`）、**启用Hook数据转发**（`sendHookData`）及其地址（默认 `http://127.0.0.1:9527/hook`）。

**运行表现**

- **为目标应用申请后台运行权限**（`batteryPerm`，默认 true）、**记录record日志**（默认 true）、**记录runtime日志**（默认 false）、**气泡提示**（默认 true）、**开启状态栏禁删**（默认 false）、**只显示中文并设置时区**（默认 true）、**气泡纵向偏移**（默认 99）、**气泡前缀**。
- **解锁**：启用内置解锁（默认 false）、锁屏类型、锁屏密码（UI/日志脱敏）、解锁超时(秒)（默认 15，范围 3~60）、解锁重试次数（默认 3，范围 1~5）。

**任务执行控制**

- **任务最大并发数**（`taskMaxConcurrency`，默认 3）：TaskRunner 的模块级并发信号量。
- **任务默认超时(毫秒)**（`taskDefaultTimeout`，默认 10 分钟）。
- **任务超时白名单**（`taskTimeoutWhitelist`，默认 `["森林", "庄园"]`）：白名单任务采用 30 秒启动超时——启动后即视为完成、不 join 等待（见 `task/TaskRunner.kt`）。

## 4. 森林组（FOREST）

### 4.1 蚂蚁森林（AntForest）

核心功能模块（`task/antForest/AntForest.kt`），继承 `ModelTask` 并实现 `EnergyCollectCallback`。职责由多个协作者分解：`ForestEnergyCollector`（能量收取）、`ForestItemManager`（道具）、`ForestShieldManager`（保护罩）、`ForestStatistics`（统计）、`EnergyWaitingManager`（蹲点，见 §4.1.7）。

执行主体是 `runSuspend()` 中的 `TaskStep` 列表（L717 起，共 30+ 步），按序执行：「查询道具状态 → 使用自己道具卡 → 找能量收取 → 收PK好友能量 → 收取自己的能量 → 1V1能量挑战 → 收取好友能量 → 拼手速 → 7天签到 → …」。

#### 4.1.1 能量收取

- **收集能量 | 开关**（`collectEnergy`，默认 false）：主开关。
- **一键收取 | 开关**（`batchRobEnergy`，默认 false）：批量收取好友能量。
- **收自己单个能量球 | 方式**（`CollectSelfEnergyType`，默认「所有」）+ **阈值**（`CollectSelfEnergyThreshold`，默认 0）：所有 / 大于阈值 / 小于阈值。
- **蹲点精度**：提前时间(毫秒)（`advanceTime`，默认 0）、尝试收取(次数)（`tryCount`，默认 1）、重试间隔(毫秒)（`retryInterval`，默认 1200）、循环间隔(毫秒)（`cycleinterval`，默认 5000）。
- **平衡网络延迟**（`balanceNetworkDelay`，默认 true，**少数默认开启项**）：根据请求耗时微调提前量。
- **不收能量 | 配置列表**（`dontCollectList`）、**收取浇水金球 | 开关**（`collectWateringBubble`，默认 false）。
- **收取翻倍能量阈值**（`robExpandCardLimt`，默认 20000，上限 20000）、**单个炸弹能量大于该值收取**（`CollectBombEnergyLimit`，默认 0）。
- **复活能量 | 选项**（`helpFriendCollectType`，默认 NONE）+ 好友列表：帮好友收/送能量。

#### 4.1.2 能量挑战与游戏

- **Pk榜收取 | 开关**（`pkEnergy`，默认 false）。
- **1V1能量挑战 | 领奖**（`energyPvpChallenge`，默认 false）：由 `EnergyPvpChallengePolicy` 决策。
- **能量雨 | 开关**（`energyRain`，默认 false）+ 执行时间（`energyRainTime`，默认 0810）+ **兑换使用能量雨次卡**（`energyRainChance`，默认 false）+ 赠送列表（`giveEnergyRainList`）。
- **🎮 6秒拼手速**：运行模式（`whackMoleMode`，默认 0 关闭；兼容/激进）、激进模式局数（`whackMoleGames`，默认 5）、兼容模式击打数（`whackMoleMoleCount`，默认 15）、执行时间（`whackMoleTime`，默认 0820）。实现在 `WhackMole.kt`。
- **森林寻宝任务**（`forestChouChouLe`，默认 false）：`ForestChouChouLe.kt`。

#### 4.1.3 道具管理（ForestItemManager）

- **双击卡开关 | 消耗类型**（`doubleCard`，默认关闭）+ 使用次数（`doubleCountLimit`，默认 6）+ 使用时间/范围（`doubleCardTime`，默认 9 个时间点）+ **限时双击永动机**（`DoubleCardConstant`，默认 false）。
- **保护罩**：消耗类型（`shieldCard`，默认关闭）+ **限时保护永动机**（`shieldCardConstant`，默认 false）。
- **加速器开关 | 消耗类型**（`bubbleBoostCard`，默认关闭）+ 使用时间/不能范围（`bubbleBoostTime`）。
- **炸弹卡 / 1.1倍能量卡 / 隐身卡**：均为消耗类型单选（默认关闭），1.1 倍卡另有使用时间列表，隐身卡有永动机开关。
- **收集道具**（`collectProp`，默认 false）、**显示背包内容**（`showBagList`，默认 true，**少数默认开启项**）。
- **节奏控制**：查询间隔（`queryInterval`，默认 `1000-2000`）、收取间隔（`collectInterval`，默认 `1000-1500`）、双击间隔（`doubleCollectInterval`，默认 `800-2400`）。

#### 4.1.4 互助与浇水

- **小号列表**（`alternativeAccountList`）：备用账号轮换收取。
- **返水**：10克/18克/33克需收能量（`returnWater10/18/33`，默认 0 关闭）。

#### 4.1.7 蹲点等待（EnergyWaitingManager）

核心守护机制（V3 架构），详见 [任务执行流程分析.md](file:///e:/workspace/AndroidStudioProjects/Sesame-TK/docs/任务执行流程分析.md) §3：

- 多好友能量成熟时间排队等待，主任务结束时在后台协程独立运行，不阻塞主任务（`runSuspend()` finally 块 L843-845）。
- 会话级 `WaitingAccountSession` + 重试策略 `WaitingRetryPolicy`（定义于 `task/antForest/waiting/WaitingTypes.kt` L51-97，基础延迟 + ±2s 抖动）。

- 配合 `SmartSchedulerManager`（`hook/keepalive/`）保活，确保到点准时收取。

## 11. 特殊任务类（不在 ModelOrder 中）

### 11.1 MainTask（主调度任务）

`task/MainTask.kt`。特殊 `ModelTask`：构造时 `enableField.value = true`（**始终启用**，不受配置控制），`getGroup()` 返回 BASE，`check()` 恒为 true。作为主任务调度入口，驱动整轮任务循环。

- **ManualTaskModel**（`task/customTasks/ManualTaskModel.kt`）：手动任务配置模型（group=OTHER），**`check()` 恒返回 false**——确保永远不会被 TaskRunner 自动执行循环选中，仅通过 UI（`ManualTaskActivity` / `ManualTaskScreen`）或广播（`BroadcastReceiverManager` 的 MANUAL_TASK 广播）触发。

## 12. 支撑性模块

以下模块不直接对应某个支付宝业务，但为任务执行提供关键能力：

- **TaskBlacklist / defaultBlacklist**（`core/app/TaskBlacklist.kt`）：任务黑名单，屏蔽某些任务/用户。
- **EnergyWaitingManager / EnergyWaitingPersistence**（`task/antForest/`）：森林蹲点等待与持久化（蹲点引擎已下沉为会话级 `WaitingAccountSession`，详见 [任务执行流程分析.md](file:///e:/workspace/AndroidStudioProjects/Sesame-TK/docs/任务执行流程分析.md) §3）。
- **UserEnergyPatternManager**（`task/antForest/`）：用户能量成熟规律学习，辅助蹲点。

## 13. 辅助服务能力

- **内置解锁**（`service/unlock/`）：`UnlockManager` + `UnlockAccessibilityService`，解锁期间上滑 + 点按锁屏数字键。支持 PIN（三层策略）/ PASSWORD，不支持 PATTERN。
- **Shell 能力**（`service/`）：`ShellManager` 支持 Root（`SafeRootShell`，见 `service/patch/PatchedRootShell.kt`）/ Shizuku / 无 三种类型，单命令 5 秒超时；`ShizukuChecker` 检测 Shizuku 授权状态。
- **命令服务**（`service/`）：`CommandService` 前台服务（`:command` 进程），AIDL 提供 `executeCommand`（15 秒超时、串行互斥）等接口。
- **RPC 调试**（`hook/rpc/debug/`）：`DebugRpc` / `DebugRpcCall` 抓包与转发。
- **验证码处理**（`hook/captcha/` + `hook/view/`）：`CaptchaHook` 拦截验证码弹窗，`Captcha1/2Handler` 分类处理，`RpcPauseGate` 挂起等待；滑块识别由 `hook/view/SliderTFLite`（LiteRT YOLO 模型）完成，`hook/view/MotionEventSimulator` / `SystemInputSwiper` 负责模拟手势滑动。
- **HTTP 调试服务器**（`hook/server/`）：`ModuleHttpServer`（NanoHTTPD）提供 `/debugHandler`、`/getAlipayMiniMark`、`/getAuthCode` 三个路由。**仅 `BuildConfig.DEBUG` 且主进程时启动**，端口 8080，监听 `0.0.0.0`，token 硬编码于 `ApplicationHook.initHandler`。
- **保活调度**（`hook/keepalive/`）：`SmartSchedulerManager` 协程 + WakeLock 保活，保障蹲点任务到点执行。

## 14. 功能模块使用建议

1. **默认全关**：除基础模块外全部默认禁用，按需开启，避免不必要的高频请求触发风控。
2. **森林最重**：森林模块功能最重（30+ TaskStep），涉及大量道具/挑战/蹲点逻辑，建议按需开启子项；「一键收取」与「收集能量」注意配合不收列表。
3. **时间窗口配合**：「只收能量时间」期间其他任务会被自动拦截，注意与「模块休眠时间」配合避免冲突。
4. **白名单任务**：「森林/庄园」默认在超时白名单中（30 秒启动超时），主任务不会长时间阻塞等待。
5. **多账号切换**：蹲点任务会随账号切换保存/恢复快照，确保旧账号任务不污染新账号。
6. **手动任务**：`ManualTaskModel` 永不自动执行，需在 UI「手动任务」页或通过广播触发，与自动任务互斥。
