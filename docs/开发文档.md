# Sesame-TK 开发文档

> 芝麻粒-TK（Sesame-TK）是一个基于 LSPosed / Xposed 框架的 Android 模块，通过对支付宝（`com.eg.android.AlipayGphone`）进行 Hook，实现蚂蚁森林、庄园、海洋、新村等各类任务的自动化执行。本文档面向模块开发者，介绍项目架构、技术栈、关键设计及二次开发指南。

### 3.2 双 Hook 入口设计

项目同时兼容现代 LSPosed（libxposed 102）与传统 Xposed（82）后端，通过双入口统一调用：

- **legacy 入口**：`assets/xposed_init` 声明 `hook.entry.legacy.LegacyEntry`（实现 `IXposedHookLoadPackage`），框架通过 `handleLoadPackage` 调用。注入 `Xp82Hooker` 后端。
- **现代入口**：`resources/META-INF/xposed/java_init.list` 声明 `hook.entry.modern.HookEntry`（继承 `XposedModule`），+ `module.prop` 声明 `minApiVersion=82`、`targetApiVersion=102`、`staticScope=true`。在 `onModuleLoaded` 注入 `Lsp102Hooker` 后端，`onPackageLoaded` 中执行 Hook。

两入口均通过 `hook/compat/Hooker` 抽象层注入对应后端（`Hooker.install()` 互斥，仅允许一次注入），最终都会调用 `ApplicationHook().loadPackage(classLoader, packageName, apkPath)`，其参数均限定为框架无关类型，从而保证双后端共用一套 Hook 逻辑。进程名由双入口统一写入 `XposedEnv.processName`。

> 见 `hook/entry/legacy/LegacyEntry.kt`、`hook/entry/modern/HookEntry.kt`、`hook/compat/Hooker.kt`、`ApplicationHook.kt` 与 `XposedEnv.kt`。

**兼容层（hook/compat/）要点**：

- `HookParam` 统一语义：`result` 在 before 设值 = 短路原方法；after 设值 = 篡改返回值；`throwable` after 阶段可读/清除/替换。
- `Lsp102Hooker`：把 libxposed 的 OkHttp 风格拦截器链（`Chain`）适配为 before/after 双阶段；`ExceptionMode.PASSTHROUGH` 保证 proceed 异常可传播；args 为快照数组。
- `Xp82Hooker`：直接把 `HookCallback` 适配为 `XC_MethodHook`，原生语义直通映射；`deoptimize` 通过反射调用 LSPosed 私有 API，原版 Xposed 自动降级。

### 3.3 进程模型

- **Hook 进程**：仅 Hook 支付宝主进程（`shouldHookProcess()` 判断 `finalProcessName == PACKAGE_NAME`），避免辅助进程重复初始化。
- **CommandService 进程**：`process=":command"` 独立前台服务进程，通过 AIDL 提供 Shell（Root/Shizuku）命令执行与解锁能力，与 Hook 进程解耦。
- **双进程通信**：依赖 AIDL（`ICommandService`）跨进程回调（`ICallback`、`IStatusListener`）。

## 4. 关键子系统

### 4.1 启动与初始化流程（ApplicationHook）

`SesameApplication.onCreate()` 初始化全局单例（Toast、Log、主题、UI 模式仓库），并启动 `CommandService`。

Hook 侧初始化由 `ApplicationHook` 驱动，流程如下：

1. **进程检查** → 仅处理目标进程。
2. **基础 Hook**：`ModuleStatus.detectFramework()` 检测框架，`VersionHook.installHook` 捕获支付宝版本，`initReflection` 预热反射。
3. **功能 Hook**：`CaptchaHook.setupHook`（验证码拦截）、`WebViewHook.installHook`（WebView 调试）。
4. **生命周期 Hook**：
   - `hookApplicationAttach` → 初始化协程调度器、SecurityBody / 小程序标记 / 定位 / 授权码助手，加载 so（DexKit、TFLite、GPU）。
   - `hookLauncherResume` → 登录态 / 账号切换检测，初始化用户数据。
   - `hookServiceLifecycle` → 在支付宝前台服务（`RuntimePowerService`）创建时初始化 DexKit、创建主任务、启动调度。
5. **`initHandler()` 核心初始化**：加载配置、启动通知、选择 RPC 桥（`NewRpcBridge` / `OldRpcBridge`）、`Model.initAllModel()`、`Model.bootAllModel()`、`TokenHooker.start(userId)`、设置零点唤醒闹钟等。

### 4.2 任务调度体系

调度核心是 `TaskScheduler` + `SmartSchedulerManager`（详见[任务执行流程分析](file:///e:/workspace/AndroidStudioProjects/Sesame-TK/docs/任务执行流程分析.md) §2）。

- **SmartSchedulerManager**：基于「协程 + WakeLock」的自研调度器。使用 WakeLock 确保 delay 期间 CPU 不休眠（对抗 Doze），`delayWithWakeLock` 支持带锁等待，`schedule` 支持命名任务自动替换，防止重复调度堆积。
- **TaskScheduler**：负责主任务触发。`runMainTaskLogic()` 通过 `TaskLock` 互斥防止重入，检查登录态与执行间隔后，在 `applicationScope` 中启动 `CoroutineTaskRunner`。`scheduleNextExecutionInternal` 根据 `checkInterval`（默认 50 分钟）与 `execAtTimeList`（默认 12 个定点时刻）计算下一次执行时间。
- **CoroutineTaskRunner**：并发任务执行器。使用 `Semaphore` 限制最大并发（`taskMaxConcurrency` 默认 3），按配置轮数执行多轮，支持「超时白名单」——白名单任务（默认森林/庄园）为 30 秒**启动超时**：`startTask()` 返回后仍在后台运行即视为成功，不 join 等待完成；普通任务超时（默认 10 分钟）则 `stopTask()`。

**任务执行模型 `ModelTask`**：所有任务继承 `ModelTask`，提供：

- `taskScope`：任务级协程作用域（`SupervisorJob`），统一命名。
- `executionMutex`：互斥锁，防止重复执行。
- `childTaskMap`：子任务管理，`addChildTask` 支持定时/延时子任务，配合 `SmartSchedulerManager` 保活。
- `startTask(force, rounds)`：启动入口，检查启用状态与 `check()`（含能量时间/休眠时间拦截），多轮顺序执行并统计。
- `stopTask()`：取消作用域并异步清理子任务。

### 4.3 配置模型框架（Model / ModelField）

所有功能模块（含任务）都作为 `Model` 子类注册，通过 `ModelOrder.allConfig` 声明顺序，由 `Model.initAllModel()` 反射实例化。

- **Model**：抽象基类，提供 `getName / getGroup / getIcon / getFields`，生命周期 `prepare / boot / destroy`，以及启停控制。除「基础」模块默认启用外，其余模块**默认禁用**。
- **ModelField\<T\>**：配置项抽象，序列化到配置 JSON。值通过 `value` 持有，支持 `getConfigValue / setConfigValue / reset`，并在 `viewData` 中输出给 UI 渲染。
- **ModelField 子类**（`model/modelFieldExt/`）：
  - `BooleanModelField` 开关
  - `IntegerModelField` 整数
  - `StringModelField` / `TextModelField` 文本
  - `ChoiceModelField` 单选
  - `SelectModelField` / `SelectOneModelField` / `SelectAndCountModelField` / `SelectAndCountOneModelField` 选择+数量
  - `ListModelField` 列表
  - `EmptyModelField` 占位/只读
- **SesameConfig**（`model/SesameConfig.kt`）：全局运行时配置对象（非持久化字段容器），由 `ApplicationHook.config` 持有，字段默认值与范围集中定义于此（如 `checkInterval` 50 分钟、`taskMaxConcurrency` 3、`taskDefaultTimeout` 10 分钟、`taskTimeoutWhitelist` 默认「森林/庄园」）。

**配置持久化**（`data/Config.kt`）：由于 `ModelField` 是抽象类，Jackson 无法直接构造实例，因此配置加载通过解析 JSON 树手动将值应用回字段（`applyModelFieldsJson`）。配置文件按用户隔离存储于 `/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-TK/config/<userId>/config_v2.json`。

### 4.4 RPC 通信体系

任务通过 RPC 调用支付宝内部接口，核心抽象为 `RpcBridge`：

- `requestString / requestObject`：发送请求（支持方法名 + 参数 + 关联数据），带默认重试参数（`tryCount=3`），返回字符串或解析后的 `RpcEntity`。
- **双实现**：
  - `NewRpcBridge`：走支付宝新 RPC 链路（`com.alibaba.ariver.commonability.network.rpc.RpcBridgeExtension`），最低支持支付宝 v10.3.96.8100；含安全验证文案自动拉起滑块、网络错误码离线判定。
  - `OldRpcBridge`：旧接口实现（`H5RpcUtil.rpcCall`），含「系统繁忙」「登录超时」等错误处理。
  - 通过 `config.newRpc`（默认 true）在 `initHandler` 运行时选择；仅 newRpc=true 时安装 RPC 拦截 Hook。
- **TokenHooker**（`hook/rpc/TokenHooker.kt`）：RPC 分发注册表（方法名 → 处理器）。实际拦截在 `HookUtil.hookRpcBridgeExtension`（Hook `RpcBridgeExtension.rpc` 17 参方法），Hook 回调里调 `TokenHooker.handleRpc` 分发；同时注册庄园 referToken 抓取与验证码信号监听。
- **三层限流**（`hook/rpc/intervallimit/GlobalRpcRateLimiter.acquire`）：
  1. `RpcPauseGate.awaitSendable()`：验证码期间挂起/丢弃请求；
  2. per-method 间隔：`IntervalLimit` / `FixedOrRangeIntervalLimit` 限制同接口最小发送间隔；
  3. 全局并发：内建 `Semaphore` 限制同时在途 RPC 请求数，**默认并发 2**（代码内硬编码，修改 `maxConcurrency` 变量不会重建信号量，实际不可配置）。
  它与任务层的 `taskMaxConcurrency`（模块级并发，默认 3）相互独立：先限模块数，模块内部每个 RPC 请求再受此 RPC 层并发约束。
- **`RequestManager.requestString`**（`hook/RequestManager.kt`）：任务层统一入口，含离线检查、网络/Bridge 就绪等待、连续失败熔断（达 `setMaxErrorCount` 阈值置离线并重启支付宝）。另有类型化 fail-fast 入口 `requestStringResult`（区分 OFFLINE/NETWORK/BRIDGE_UNAVAILABLE/EMPTY_RESPONSE/UNKNOWN 五类失败，供蹲点引擎使用）。

### 4.5 验证码处理（captcha/ + view/）

两代验证码处理链路（详见 `hook/captcha/` 源码注释）：

- `CaptchaHook`：门面。按支付宝版本（≤ 12.99.99.99999 启用）向 `PageMonitor` 注册路由——`XRiverActivity`/`CaptchaDialog` → `Captcha1Handler`（原生 View 树，XPath 盲滑）；`XRiverTransActivity$Main` / `NebulaTransActivity$Main` → `Captcha2Handler`（WebView H5，模型识别）。另 Hook `RdsHandler.openRdsCaptchaPage` 激活暂停闸门。
- `CaptchaRpcSignal`：监听 `alipay.security.antcaptcha.verify` RPC 作为验证码信号（15 秒窗口），激活闸门并启动锚点监听。
- `RpcPauseGate`：RPC 暂停闸门。激活后挂起后续 RPC；超时（取 `taskDefaultTimeout`）后**取消（丢弃）**挂起请求而非放行；验证码处理完成经 `onCaptchaHandled` 放行。
- `CaptchaAnchorWatcher`：闸门暂停期间轮询探测验证码文案，文案消失连续 2 次确认后放行（覆盖手动滑块场景）。
- `SliderTFLite`（`hook/view/`）：加载 `slider.tflite`（LiteRT YOLO 检测模型，gap/block/refresh/feedback 四类）识别滑块缺口；模型资产经 `HookUtil.hookAssetManagerForModel` 重定向到私有目录；共享实例 + 空闲 1 小时自动卸载。
- `MotionEventSimulator` / `SystemInputSwiper`（`hook/view/`）：双路径手势模拟——前者进程内 View 级 `dispatchTouchEvent`（拟人轨迹：加速-减速-回拨）；后者系统级 `input swipe/tap` shell 兜底（Root/Shizuku）。`BaseCaptchaHandler.dispatchSwipeWithFallback` 优先前者、失败退后者。

### 4.6 内置服务

- **CommandService**（前台服务，`:command` 进程）：通过 `ShellManager` 执行 Root/Shizuku 命令，提供 AIDL 接口：`executeCommand`（15 秒超时、串行互斥）、`requestUnlock`、`findNodeByText`（借道无障碍服务检索节点，可下钻 WebView），并通过 `IStatusListener` 广播 Shell 类型状态变化。
- **ModuleHttpServer**（NanoHTTPD）：提供 `/debugHandler`（带 token 鉴权）、`/getAlipayMiniMark`、`/getAuthCode`（后两者无鉴权）调试接口。**仅 `BuildConfig.DEBUG` 且主进程时启动**，端口 8080，监听 `0.0.0.0`。路由由 `hook/server/handlers/` 下 Handler 分别实现。
- **解锁能力**（`service/unlock/`）：`UnlockManager` 编排解锁流程（亮屏 → dismiss-keyguard/上滑兜底 → 锁屏类型检测 → PIN 三层策略 / PASSWORD 输入 → 验证，PATTERN 不支持）；`UnlockAccessibilityService` 提供上滑手势、节点点击 PIN、文本输入与节点检索。
- **Shell 能力**（`service/`）：`ShellManager` 依 Root（`SafeRootShell`，见 `service/patch/PatchedRootShell.kt`）优先、Shizuku 次之选择执行器（无普通 shell 回退），单命令 5 秒超时；`ShizukuChecker` 检测授权状态。
- **LSPosed 服务管理**：`LsposedServiceManager`（`service/LsposedServiceManager.kt`）提供与 LSPosed 框架的交互能力。

### 4.7 UI 体系

- **主界面**（`ui/MainActivity.kt` + `ui/screen/MainScreen.kt`）：Compose 单 Activity，底部导航 3 个 tab（日志 / 主页 / 设置），内容直接 `when` 分发到 `HomeContent / LogsContent / SettingsContent`，无 Navigation-Router。
- **配置页双模式**：`ConfigRepository` 持久化 `uiMode`（Web / New），`performNavigationToSettings()` 据此跳转：
  - Web 模式 → `ui/legacy/WebSettingsActivity`：WebView 加载 `assets/web/semi_index.html`，经 JS 桥 `window.HOOK` 与 `Model.getModelConfigMap()` 交互；
  - New 模式 → `ui/legacy/SettingActivity` + `SettingScreen`：Compose 直接渲染 Model/ModelField。
- **辅助页**：`ExtendActivity`（扩展功能）、`LogViewerActivity`（高性能日志查看）、`RpcDebugActivity`（RPC 调试）、`ManualTaskActivity`（手动任务，经广播下发到支付宝进程）。
- **图标隐藏**：`MainActivityAlias`（activity-alias 持有 LAUNCHER）动态启停实现。

### 4.8 数据与工具

- **Files**（`core/app/Files.kt`）：统一文件读写，管理配置/日志/导出目录（根目录 `/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-TK/`），带权限检查与写重试。
- **Log**：`record / debug / error / printStackTrace` 分级日志，写入 record/debug/forest/farm/other/error 等日志文件。
- **Notify**：前台通知状态栏，展示任务执行状态、下次执行时间。
- **DataStore**：通用 KV 存储（`activedUser` 等）。
- **maps/**：`IdMapManager` 管理各类 ID 映射（Beach/Cooperate/User/MemberBenefits/Reserve/SesameGift 等），支持内存缓存与持久化。

## 5. 构建指南

### 5.1 环境要求

- JDK 17
- Android SDK（compileSdk 37）
- Gradle（由 `gradlew` wrapper 提供）
- 可选：NDK 29.0.14206865（仅当存在 `src/main/cpp` 时启用 CMake 构建）

### 5.2 构建命令

```bash
# Debug 构建
./gradlew assembleDebug

# Release 构建（开启 R8 混淆 + 资源收缩）
./gradlew assembleRelease

# 仅跑单元测试
./gradlew testDebugUnitTest -PenableUnitTests=true
```

APK 按 ABI 拆分（armeabi-v7a / arm64-v8a / x86 / x86_64 / universal）。

### 5.3 签名

签名信息优先级：环境变量（CI secrets）> 根目录 `keystore.properties` > 根目录 `keystore.jks`。缺失时 release 自动回退 debug 签名。产物统一命名：`Sesame-TK-<abi>-<variant>-v<version>.apk`，并额外复制带时间戳的交付件到 `build/outputs/renamed_apks/`。

### 5.4 环境变量

| 变量 | 说明 |
| --- | --- |
| `ANDROID_KEYSTORE_PATH` | 签名 keystore 路径 |
| `ANDROID_KEYSTORE_PASSWORD` | 密钥库密码 |
| `ANDROID_KEY_ALIAS` | 别名 |
| `ANDROID_KEY_PASSWORD` | 密钥密码 |
| `CI` | 设为 true 开启 CI 构建（自动包含全部 ABI、跳过本地 CMake） |

### 5.5 CI

- `.github/workflows/android.yml`：Release 流水线，**仅 Release published 触发**。JDK 17 → `assembleRelease -Pversion=<tag>`（secrets 解码 keystore 签名）→ 定位 5 个 ABI APK → sha256 校验和 → 发布 GitHub Release → 用 PAT 同步到 `Xposed-Modules-Repo/fansirsqi.xposed.sesame`。
- `.github/workflows/debug.yml`：Debug 流水线，push/PR + 手动触发，仅上传 Artifacts。

## 6. 二次开发指南

### 6.1 新增一个业务任务模块

1. **创建任务类**：继承 `ModelTask`（或直接继承 `Model` 若为配置型模块），实现 `getName()`、`getGroup()`、`getIcon()`、`getFields()`，并重写 `runSuspend()` / `runJava()` 编写业务逻辑。
2. **注册模块**：在 `ModelOrder.kt` 的 `array` 中加入任务类，控制其在 UI 中的展示顺序。
3. **配置字段**：在 `getFields()` 中通过 `ModelFields.addField(...)` 添加 `config.<某字段>`，字段在 `SesameConfig` 中声明并作为 `ModelField` 实例。
4. **RPC 调用**：在任务内通过 `RequestManager.requestString(RpcEntity, ...)` 或 `RpcBridge` 调用支付宝接口；如需拦截/注入请求，可向 `TokenHooker` 注册方法名处理器。
5. **图标**：将图标放入 `assets/web/images/icon/model/`（含 `selected/` 选中态），并在 `getIcon()` 返回文件名。

### 6.2 任务执行注意事项

- **并发限制**：遵守 `taskMaxConcurrency`，避免高频 RPC 触发风控；必要时在任务内部用 `Semaphore` 控制子请求并发。
- **频率限制**：注册 `GlobalRpcRateLimiter.addIntervalLimit` 约束接口调用频率。
- **时间窗口**：`check()` 中已内置「只收能量时间」与「模块休眠时间」拦截，若任务需要在特定时段运行，请在 `getFields()` 中配置时间字段并自行判断。
- **超时处理**：长驻型任务（如蚂蚁森林、庄园）加入 `taskTimeoutWhitelist` 白名单——注意白名单不是「无超时」，而是 30 秒启动超时 + 后台继续运行不计失败。

### 6.3 代码风格与约定

- 全项目 Kotlin，遵循 Compose 状态管理（`StateFlow` + ViewModel）。
- 日志统一走 `Log.record/debug/error`，禁止直接 `System.out`。
- 运行时全局配置集中定义于 `SesameConfig`，任务私有配置作为 `ModelField` 在各任务 `getFields()` 中声明。
- 涉及目标应用类名常量集中放 `General` 或对应 Helper 中，保持可维护。
- Hook 相关能力（hook 注册 / 原方法调用 / 反优化 / 框架日志）一律经 `Hooker.get()` 使用，不得直接引用具体框架 API。

## 7. 常见问题与排错

- **Hook 未生效**：确认模块作用域勾选支付宝、`scope.list` 包含目标包名、框架版本 ≥ 82；若用原版 Xposed 走 legacy 入口，LSPosed 走 modern 入口，两者由 `module.prop` / `xposed_init` 声明。
- **日志为空**：检查 `recordLog` / `runtimeLog` 开关；查看 `/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-TK/log/` 下对应日志文件。
- **RPC 请求失败**：确认 `newRpc` 开关与支付宝版本匹配（新接口最低 v10.3.96.8100），检查是否触发频率限制或验证码；可在 debug 模式开启 `ModuleHttpServer` 抓包（`/debugHandler`）。
- **验证码不处理**：确认支付宝版本 ≤ 12.99.99.99999（版本门槛）、目标页面属于已路由的 Activity/Dialog 类型；滑块识别依赖 `slider.tflite` 模型资产重定向是否成功。
- **解锁失败**：确认无障碍服务已开启、Shizuku/Root 权限就绪、配置了正确的锁屏密码/类型（PATTERN 不支持）。
