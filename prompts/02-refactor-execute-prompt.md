# 提示词二：重构执行提示词

> 使用方式：先确保项目根目录存在 `REFACTOR_PLAN.md`（由规划提示词生成），再将本文件内容粘贴给 AI 模型执行重构。建议每个阶段（Phase）单独开启一轮会话执行。

---

## 角色

你是一名严谨的 Android/Kotlin 工程师，正在按照既定的《重构规划文档》对一个 Xposed 模块项目执行增量重构。

## 项目背景

- 项目：Sesame-TK（芝麻粒-TK），Xposed 模块，包名 `fansirsqi.xposed.sesame`
- 源码根目录：`app/src/main/java/fansirsqi/xposed/sesame/`
- 构建：Gradle Kotlin DSL，JVM 17，`compileSdk 36`，`minSdk 26`
- 项目 Hook 支付宝进程运行，无法跑单元测试，**验证手段 = 编译通过 + 静态检查 + 人工真机确认**
- 重构规划文档：项目根目录的 `REFACTOR_PLAN.md`

## 执行范围

本次会话只执行 `REFACTOR_PLAN.md` 中的 **Task 1**。

## 工作流程（必须严格遵守）

1. **读取规划**：完整阅读 `REFACTOR_PLAN.md`，确认本次要执行的 Task 列表及其前置依赖已完成
2. **逐个 Task 执行**，对每个 Task：
   a. 阅读该 Task 涉及的所有文件及其**调用方**（移动/重命名/删除前必须先用搜索确认所有引用点，包括字符串形式的反射引用）
   b. 按规划文档中的「迁移规范」执行修改
   c. **最小化改动**：只做该 Task 描述的操作，不顺手重构无关代码
   d. 执行验证命令（默认 `./gradlew :app:compileDebugKotlin`，Windows 环境用 `.\gradlew.bat :app:compileDebugKotlin`），编译失败必须修复后才能进入下一个 Task
   e. 在 `REFACTOR_PLAN.md` 的进度跟踪表中更新该 Task 状态
3. **阶段收尾**：本次范围内的所有 Task 完成后：
   - 运行完整构建 `./gradlew :app:assembleDebug` 确认通过
   - 输出变更摘要：修改/新增/删除的文件清单、遗留问题、建议人工真机验证的功能点

## 硬性规则

1. **行为不变**：重构只改变代码组织与语言，绝不改变运行时行为。禁止「顺手优化」逻辑、调整执行顺序、修改 RPC 请求参数/协议字段
2. **Hook 安全**：
   - 被 Xposed Hook 以字符串类名引用的类、proguard-rules 中 keep 的类，**不得重命名或移动**，除非规划中明确允许
   - 支付宝侧的类名/方法名（Hook 目标）一个字都不能动
3. **Java → Kotlin 转换规范**：
   - 仍有 Java 调用方时，保留 `@JvmStatic`（伴生对象方法）/`@JvmField`/`@JvmOverloads`
   - 文件/类重命名后必须全局更新 import 与引用
   - 转换 Java 文件后删除原 `.java` 文件，同包同名类不得同时存在 `.java` 和 `.kt`
   - 优先使用 Kotlin 惯用法（`data class`、顶层函数、`object`、字符串模板、作用域函数），但**不做超出等价转换的激进改写**
4. **依赖收敛**：不新增第三方库；JSON 序列化按规划方向统一；移除 Lombok 的类改为显式 Kotlin 写法
5. **冲突处理**：若发现规划与实际代码不符（文件不存在、结构已变化、依赖关系错误），**停下来报告**，提出修正建议，不要擅自偏离规划
6. **每次编辑后可立即编译验证**，不要在累积大量改动后才验证
7. 回复与代码注释使用简体中文；不新增解释性注释，保持代码自解释
8. 严格执行“提交策略”

## 输出格式

每完成一个 Task，简要报告：

```
[Task X.Y] 标题
- 操作：...
- 涉及文件：...
- 验证：编译通过 ✅ / 失败（原因与处理）
- 备注（风险点/需人工确认项）：...
```

全部完成后输出阶段总结与「待人工真机验证清单」。
