# Sesame-TK 开发文档

> 芝麻粒-TK（Sesame-TK）是一个基于 LSPosed / Xposed 框架的 Android 模块，通过对支付宝（`com.eg.android.AlipayGphone`）进行 Hook，实现蚂蚁森林、庄园、海洋、新村等各类任务的自动化执行。本文档面向模块开发者，介绍项目架构、技术栈、关键设计及二次开发指南。

## 3. 架构设计

### 3.1 总体分层

项目遵循清晰的分层结构，从上到下依次为：

```
┌─────────────────────────────────────────────────────┐
│                       UI 层 (ui/)                    │
│    Compose 主界面 / 设置 / 日志查看 / RPC 调试          │
└─────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────┐
│                   功能任务层 (task/)                  │
│    AntForest / AntFarm / AntOcean / ... 各业务任务    │
│    ModelTask 抽象基类 + CoroutineTaskRunner 执行器    │
└─────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────┐
│                   配置模型层 (model/)                 │
│    Model / ModelField 框架，配置项抽象与持久化          │
└─────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────┐
│                      Hook 层 (hook/)                 │
│    ApplicationHook 入口、RPC 桥、验证码、视图模拟       │
│    TokenHooker 拦截、TaskScheduler 调度、内置服务器     │
└─────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────┐
│                  核心基础层 (core/)                   │
│    文件 / 日志 / 通知 / 反射 / 线程池 / 通用工具        │
└─────────────────────────────────────────────────────┘
```

### 3.2 双 Hook 入口设计

项目同时兼容现代 LSPosed（libxposed 102）与传统 Xposed（82）后端，通过双入口统一调用：

- **legacy 入口**：`assets/xposed_init` 声明 `hook.entry.legacy.LegacyEntry`（实现 `IXposedHookLoadPackage`），框架通过 `handleLoadPackage` 调用。注入 `Xp82Hooker` 后端。
- **现代入口**：`resources/META-INF/xposed/java_init.list` 声明 `hook.entry.modern.HookEntry`（继承 `XposedModule`），+ `module.prop` 声明 `minApiVersion=82`、`targetApiVersion=102`、`staticScope=true`。在 `onModuleLoaded` 注入 `Lsp102Hooker` 后端，`onPackageLoaded` 中执行 Hook。

两入口均通过 `hook/compat/Hooker` 抽象层注入对应后端（`Hooker.install()` 互斥，仅允许一次注入），最终都会调用 `ApplicationHook().loadPackage(classLoader, packageName, apkPath)`，其参数均限定为框架无关类型，从而保证双后端共用一套 Hook 逻辑。进程名由双入口统一写入 `XposedEnv.processName`。

> 见 `hook/entry/legacy/LegacyEntry.kt`、`hook/entry/modern/HookEntry.kt`、`hook/compat/Hooker.kt`、`ApplicationHook.kt` 与 `XposedEnv.kt`。

### 3.3 进程模型

- **Hook 进程**：仅 Hook 支付宝主进程（`shouldHookProcess()` 判断 `finalProcessName == PACKAGE_NAME`），避免辅助进程重复初始化。
- **CommandService 进程**：`process=":command"` 独立前台服务进程，通过 AIDL 提供 Shell（Root/Shizuku）命令执行与解锁能力，与 Hook 进程解耦。
- **双进程通信**：依赖 AIDL（`ICommandService`）跨进程回调（`ICallback`、`IStatusListener`）。

## 4. 关键子系统

### 4.1 启动与初始化流程（ApplicationHook）

`SesameApplication.onCreate()` 初始化全局单例（Toast、Log、主题、配置仓库），并启动 `CommandService`。

Hook 侧初始化由 `ApplicationHook` 驱动，流程如下：

1. **进程检查** → 仅处理目标进程。
2. **基础 Hook**：`ModuleStatus.detectFramework()` 检测框架，`VersionHook.installHook` 捕获支付宝版本，`initReflection` 预热反射。
3. **功能 Hook**：`CaptchaHook.setupHook`（验证码拦截）、`WebViewHook.installHook`（WebView 调试）。
4. **生命周期 Hook**：
   - `hookApplicationAttach` → 初始化协程调度器、SecurityBody / 小程序标记 / 定位 / 授权码助手，加载 so（DexKit、TFLite、GPU）。
   - `hookLauncherResume` → 登录态 / 账号切换检测，初始化用户数据。
   - `hookServiceLifecycle` → 在支付宝前台服务（`RuntimePowerService`）创建时初始化 DexKit、创建主任务、启动调度。
5. **`initHandler()` 核心初始化**：加载配置、启动通知、选择 RPC 桥（`NewRpcBridge` / `OldRpcBridge`）、`Model.initAllModel()`、`Model.bootAllModel()`、`TokenHooker.start(userId)`、设置零点唤醒闹钟等。

### 4.2 任务调度体系

调度核心是 `TaskScheduler` + `SmartSchedulerManager`。

- **SmartSchedulerManager**：基于「协程 + WakeLock」的自研调度器，替代 AlarmManager 广播地狱。使用 WakeLock 确保 delay 期间 CPU 不休眠（对抗 Doze），`delayWithWakeLock` 支持带锁等待，`schedule` 支持命名任务自动替换，防止重复调度堆积。
- **TaskScheduler**：负责主任务触发。`runMainTaskLogic()` 通过 `TaskLock` 互斥防止重入，检查登录态与执行间隔后，在 `applicationScope` 中启动 `CoroutineTaskRunner`。`scheduleNextExecutionInternal` 根据 `checkInterval` 与 `execAtTimeList`（定时执行点）计算下一次执行时间。
- **CoroutineTaskRunner**：并发任务执行器。使用 `Semaphore` 限制最大并发（防风控），按配置轮数执行多轮，支持「超时白名单」——如蚂蚁森林这类长驻守护型任务启动即视为完成、后台自行调度；普通任务超时则 `stopTask()`。

**任务执行模型 `ModelTask`**：所有任务继承 `ModelTask`，提供：

- `taskScope`：任务级协程作用域（`SupervisorJob`），统一命名。
- `executionMutex`：互斥锁，防止重复执行。
- `childTaskMap`：子任务管理，`addChildTask` 支持定时/延时子任务，配合 `SmartSchedulerManager` 保活。
- `startTask(force, rounds)`：启动入口，检查启用状态与 `check()`（含能量时间/休眠时间拦截），多轮顺序执行并统计。
- `stopTask()`：取消作用域并异步清理子任务。

### 4.3 配置模型框架（Model / ModelField）

所有功能模块（含任务）都作为 `Model` 子类注册，通过 `ModelOrder.allConfig` 声明顺序，由 `Model.initAllModel()` 反射实例化。

- **Model**：抽象基类，提供 `getName / getGroup / getIcon / getFields`，生命周期 `prepare / boot / destroy`，以及启停控制。
- **ModelField\<T\>**：配置项抽象，序列化到配置 JSON。值通过 `value` 持有，支持 `getConfigValue / setConfigValue / reset`，并在 `viewData` 中输出给 UI 渲染。
- **ModelField 子类**（`model/modelFieldExt/`）：
  - `BooleanModelField` 开关
  - `IntegerModelField` 整数
  - `StringModelField` / `TextModelField` 文本
  - `ChoiceModelField` 单选
  - `SelectModelField` / `SelectOneModelField` / `SelectAndCountModelField` / `SelectAndCountOneModelField` 选择+数量
  - `ListModelField` 列表
  - `EmptyModelField` 占位/只读

**配置持久化**（`Config.kt`）：由于 `ModelField` 是抽象类，Jackson 无法直接构造实例，因此配置加载通过解析 JSON 树手动将值应用回字段（`applyModelFieldsJson`）。配置文件按用户隔离存储于 `/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-TK/config/<userId>/config_v2.json`。

### 4.4 RPC 通信体系

任务通过 RPC 调用支付宝内部接口，核心抽象为 `RpcBridge`：

- `requestString / requestObject`：发送请求（支持方法名 + 参数 + 关联数据），带默认重试参数，返回字符串或解析后的 `RpcEntity`。
- **双实现**：
  - `NewRpcBridge`：走支付宝新 RPC 链路（`RpcBridgeExtension`），由 `HookUtil.hookRpcBridgeExtension` 拦截。
  - `OldRpcBridge`：旧接口实现。
  - 通过 `config.newRpc` 开关在运行时选择。
- **TokenHooker**（`hook/rpc/TokenHooker.kt`）：拦截 RPC 请求（在 `RpcBridgeExtension.rpc` 的 before 回调中解析 `com.alibaba.fastjson.JSONObject`），并将请求分发给各任务的 `RpcCall` 处理器，同时负责 token 相关处理。
- **频率控制**：`GlobalRpcRateLimiter`（`hook/rpc/intervallimit/`）+ `IntervalLimit` / `FixedOrRangeIntervalLimit` 限制接口调用频率，防止风控。
- **`RequestManager.requestString`**（`hook/RequestManager.kt`）：任务层统一入口。

### 4.5 验证码处理（captcha/ + view/）

- `CaptchaHook`（`hook/captcha/`）：拦截验证码弹窗 RPC。
- `BaseCaptchaHandler` / `Captcha1Handler` / `Captcha2Handler`（`hook/captcha/`）：不同验证码类型处理。
- `CaptchaAnchorWatcher` / `CaptchaDetectionResult` / `CaptchaRpcSignal`（`hook/captcha/`）：验证码锚点监听、检测结果与 RPC 信号。
- `SliderTFLite`（`hook/view/`）：加载 `slider.tflite`（LiteRT）识别滑块缺口位置。
- `MotionEventSimulator` / `SystemInputSwiper`（`hook/view/`）：模拟手势滑动。
- `RpcPauseGate`（`hook/captcha/`）：RPC 暂停门控，处理验证码期间的请求挂起。

### 4.6 内置服务

- **CommandService**（前台服务，`:command` 进程）：通过 `ShellManager` 执行 Root/Shizuku 命令，提供 AIDL 接口：`executeCommand`、`requestUnlock`、`findNodeByText`，并通过 `IStatusListener` 广播 Shell 类型状态变化。
- **ModuleHttpServer**（NanoHTTPD，仅 debug 模式启动在 8080）：提供 `/debugHandler`、`/getAlipayMiniMark`、`/getAuthCode` 调试接口，路由由 `hook/server/handlers/` 下的 `DebugHandler` / `AlipayMiniMarkHandler` / `AuthCodeHandler` 分别实现。
- **解锁能力**：`UnlockAccessibilityService`（无障碍服务）在解锁期间执行上滑手势与点击锁屏数字键；`UnlockManager` 编排解锁流程；`ShellManager` 支持 Root / Shizuku / 无 三种 Shell 类型（见 `ShellType`），`SafeRootShell`（`service/patch/PatchedRootShell.kt`）提供增强 Root 命令执行。
- **Shizuku**：在 `AndroidManifest.xml` 中声明 Shizuku Provider，`ShizukuChecker`（`service/ShizukuChecker.kt`）检测授权，实现免 Root 命令执行。
- **LSPosed 服务管理**：`LsposedServiceManager`（`service/LsposedServiceManager.kt`）提供与 LSPosed 框架的交互能力。

### 4.7 数据与工具

- **Files**（`core/app/Files.kt`）：统一文件读写，管理配置/日志/导出目录，带权限检查与写重试。
- **Log**：`record / debug / error / printStackTrace` 分级日志，写入 record/debug/forest/farm/other/error 等日志文件。
- **Notify**：前台通知状态栏，展示任务执行状态、下次执行时间。
- **DataStore**：通用 KV 存储（`activedUser` 等）。
- **maps/**：`IdMapManager` 管理各类 ID 映射（Beach/Cooperate/User/MemberBenefits/Reserve/SesameGift 等），支持内存缓存与持久化。

## 6. 二次开发指南

### 6.1 新增一个业务任务模块

1. **创建任务类**：继承 `ModelTask`（或直接继承 `Model` 若为配置型模块），实现 `getName()`、`getGroup()`、`getIcon()`、`getFields()`，并重写 `runSuspend()` / `runJava()` 编写业务逻辑。
2. **注册模块**：在 `ModelOrder.kt` 的 `array` 中加入任务类，控制其在 UI 中的展示顺序。
3. **配置字段**：在 `getFields()` 中通过 `ModelFields.addField(...)` 添加 `config.<某字段>`，字段在 `SesameConfig` 中声明并作为 `ModelField` 实例。
4. **RPC 调用**：在任务内通过 `RequestManager.requestString(RpcEntity, ...)` 或 `RpcBridge` 调用支付宝接口；如需拦截/注入请求，可在对应 `RpcCall` 中处理。
5. **图标**：将图标放入 `assets/web/images/icon/model/`（含 `selected/` 选中态），并在 `getIcon()` 返回文件名。

### 6.2 任务执行注意事项

- **并发限制**：遵守 `taskMaxConcurrency`，避免高频 RPC 触发风控；必要时在任务内部用 `Semaphore` 控制子请求并发。
- **频率限制**：注册 `GlobalRpcRateLimiter.addIntervalLimit` 约束接口调用频率。
- **时间窗口**：`check()` 中已内置「只收能量时间」与「模块休眠时间」拦截，若任务需要在特定时段运行，请在 `getFields()` 中配置时间字段并自行判断。
- **超时处理**：长驻型任务（如蚂蚁森林、庄园）加入 `taskTimeoutWhitelist` 白名单，避免被超时中断。

### 6.3 代码风格与约定

- 全项目 Kotlin，遵循 Compose 状态管理（`StateFlow` + ViewModel）。
- 日志统一走 `Log.record/debug/error`，禁止直接 `System.out`。
- 配置项集中定义于 `SesameConfig`，UI 通过 `ConfigRepository` 与 ViewModel 桥接。
- 涉及目标应用类名常量集中放 `General` 或对应 Helper 中，保持可维护。

## 7. 常见问题与排错

- **Hook 未生效**：确认模块作用域勾选支付宝、`scope.list` 包含目标包名、框架版本 ≥ 82。
- **日志为空**：检查 `recordLog` / `runtimeLog` 开关；查看 `/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-TK/log/` 下对应日志文件。
- **RPC 请求失败**：确认 `newRpc` 开关与支付宝版本匹配，检查是否触发频率限制或验证码；可在 debug 模式开启 `ModuleHttpServer` 抓包（`/debugHandler`）。
- **解锁失败**：确认无障碍服务已开启、Shizuku/Root 权限就绪、配置了正确的锁屏密码/类型。
